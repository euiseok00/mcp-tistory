# Tistory 자동 글쓰기 MCP — MVP 확정 사항

## 목표
Claude 웹 채팅에서 요청 1회로, 현재 대화(또는 지정한 A~B 구간)를 제목·본문으로 정리해 Tistory에 **임시저장**한다.
학습 목적: MCP 서버를 직접 설계·구현

## 아키텍처
Claude 웹(Pro, 커스텀 커넥터) → HTTPS → Cloudflare quick tunnel → 로컬 PC(Docker) MCP 서버(Streamable HTTP) → Tistory 내부 API

## 확정 결정
| 항목 | 결정 |
|---|---|
| 연결 | Claude 웹 커스텀 커넥터, Streamable HTTP, 엔드포인트 `/mcp` |
| 전송 모드 | stateless + JSON 응답 모드(`enableJsonResponse: true`). quick tunnel이 SSE를 지원하지 않으므로 SSE 스트림 응답을 쓰지 않는다 |
| 구현 언어 | TypeScript (Node.js 22 LTS) + 공식 SDK `@modelcontextprotocol/sdk`. 변환 `marked`, 정리 `sanitize-html`, 티스토리 호출은 내장 `fetch` |
| 엔드포인트 인증 | OAuth 2.1 (MCP Authorization 스펙). 콜백 URL `https://claude.ai/api/mcp/auth_callback` 허용. 인증 없는 요청은 401 거부 |
| 인가 서버 | MCP 서버에 내장. SDK `mcpAuthRouter`(메타데이터·DCR·authorize·token) + `requireBearerAuth`로 `/mcp` 보호. PKCE 필수 |
| 인가 사용자 | 소유자 1명. `/authorize`에서 패스프레이즈 폼 1개, 환경변수 `OWNER_PASSPHRASE`와 `crypto.timingSafeEqual` 비교, 실패 횟수 제한 |
| 토큰 저장 | 메모리(`Map`). 재시작 시 tunnel URL·커넥터가 바뀌므로 영속 저장 안 함. access token 1시간 |
| 노출 | Cloudflare quick tunnel (임시). 재시작 시 URL 재등록. 서버·터널을 먼저 띄운 뒤 커넥터 등록 |
| 도구 | `tistory_write_post` 1개 |
| 입력 | `title`, `content_markdown` |
| 서버 처리 | 마크다운 → 티스토리 HTML 변환 → 임시저장 (발행 안 함) |
| 반환 | 성공 여부, 임시저장 글 식별자 |
| 제외(2단계) | 발행, 삭제, 수정, 태그, 카테고리, 이미지, 다이어그램 렌더링 |

## 핵심 요구사항
- 입력: `title` 1~50자, `content_markdown` 1~50,000자 (※ 가정값, 실제 제한은 테스트로 확인)
- 지원 문법: 제목, 목록, 표, 코드블록(언어 지정), 인용, 링크, 굵게/기울임 (다이어그램은 지원하지 않음. mermaid 등은 일반 코드블록으로 남는다)
- 본문의 위험한 HTML(`<script>` 등)은 제거
- 응답: 성공 `{ ok, draftId, title }` / 실패 `{ ok:false, errorCode, message }`
  - 오류 코드: `INVALID_INPUT`, `SESSION_EXPIRED`, `TISTORY_REJECTED`, `UNKNOWN`
- 도구 설명에 작성 지침 포함: 대화에 없는 내용 추가 금지, 마크다운으로 작성, 제목은 한 줄, 사용한 대화 범위를 사용자에게 한 줄로 알릴 것

## 설계 원칙
- 구간 선택(현재 채팅 / A~B)은 MCP가 아니라 Claude가 수행한다. 서버는 대화 내용을 볼 수 없다.
- 티스토리 호출부는 `TistoryClient` 인터페이스로 분리해 구현체 교체 가능하게 한다. (내부 API 변경·차단 대비)
- MCP 엔드포인트 인증(Claude → 서버, OAuth)과 티스토리 인증(서버 → 티스토리, 쿠키)은 별개로 다룬다.
- 티스토리 인증은 쿠키 세션 우선. 쿠키·비밀번호·OAuth 시크릿은 환경변수/볼륨으로 주입하고 이미지에 포함하지 않는다.
- 로그에 본문 전체와 쿠키를 남기지 않는다. 패스프레이즈·토큰도 마찬가지.

## 알려진 리스크
- 티스토리 Open API는 종료됨 → 내부 API 사용은 비공식이며 언제든 깨질 수 있고 약관상 회색지대
- 카카오 2차 인증/캡차로 자동 로그인이 막힐 수 있음
- quick tunnel URL은 공개 주소이므로 테스트 용도로만 사용하고, 미사용 시 종료 (OAuth로 무단 호출은 차단)
- quick tunnel URL이 바뀌면 OAuth 메타데이터의 issuer/resource URL도 바뀌므로 커넥터 재등록·재인증 필요
- 긴 대화에서는 앞부분이 압축되어 A~B 구간이 부정확할 수 있음

## 완료 기준 (MVP)
Claude 웹에서 요청 1회로 Tistory 임시저장함에 제목과 본문이 정상 표시된다.

**달성 (2026-10-29):** Docker + quick tunnel + Claude 웹 커스텀 커넥터(OAuth)로 E2E 성공. 검증 순서 1~4 모두 통과.

## 검증 순서
1. 로컬 단독: 서버를 HTTP 모드로 띄우고 MCP Inspector로 `tistory_write_post` 호출 → 로그인·임시저장 확인
2. Docker화: 세션/시크릿은 볼륨으로 마운트
3. 터널 + 커넥터: Claude 웹에서 OAuth 인증 통과 → 도구 목록 확인. 토큰 없는 요청은 401 확인
4. E2E: 대화에서 요청 → 티스토리 임시저장함 확인

## 확인 필요 항목
- 티스토리 에디터 HTML 모드의 코드블록·표 구조 (샘플 글로 확인)
- 제목·본문 길이 제한
- 커넥터 URL 수정 가능 여부 (불가하면 삭제 후 재등록)
- SDK 설치 버전의 `mcpAuthRouter`·`OAuthServerProvider` API (1.x 기준으로 결정함)
